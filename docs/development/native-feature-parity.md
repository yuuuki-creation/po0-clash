# 原生版功能对齐 FlClash

决定见 [ADR 0020](../adr/0020-native-feature-parity.md)：原生版要有 Flutter 版（FlClash 加本 fork）的全部功能。本页是逐项清单和实施顺序。
「已有」指原生内核和三端都已实现；「内核」「界面」两列写还缺什么。

## 导航

与 Flutter 版一致：仪表盘、代理、配置（订阅）、加白、活动（请求 / 连接 / 日志）、工具。桌面端「活动」在侧边栏里；手机上标签栏
只放仪表盘、代理、配置、加白、工具五项，「活动」从工具页进入。

### 平台功能

快捷设置磁贴（Android，已有）、托盘 / 菜单栏（已有）、Android 通知栏。

图标与托盘沿用 Flutter 版的设计，不另画：应用图标；Windows 托盘的三态图标（未连接、系统代理、虚拟网卡）；macOS 菜单栏的
po0 模板图标，连接时旁边两行显示上下行速率（默认开，可在「应用」里关）；Android 启动图标、单色主题图标和磁贴图标。

## 不做

- Firebase 崩溃上报：fork 为了匿名已移除（ADR 0006）。
- 自定义主题色、调色板：与液态玻璃规范冲突（ADR 0019），外观只提供深浅色和文字大小。

## 顺序

1. 内核：设置模型和配置生成覆盖上表全部配置项；external-controller 的连接、日志、内存、providers、规则、geo 接口与推送；
   速率历史；配置预览与导出；文件导入；备份与恢复；覆写（规则先做，JS 脚本最后）。三端的 UniFFI / Tauri 接口一起加。
2. 三端界面按导航逐页补齐，先活动页和工具页的配置表单，再代理页布局与 providers，最后覆写、备份、快捷键等。
3. 每一项在三端都做完才算完成，在本页把状态改成「已有」。
