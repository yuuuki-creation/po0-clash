# 0014. po0 与 ggy 合并为统一加白入口

- 状态：已采纳
- 日期：2026-10-10

## 背景

0013 把 ggy 提为独立页面与独立开关后，维护者要求把两个入口合并为一个「加白」功能：
一个主导航入口、一个自动加白总开关、一张混合条目列表，新增条目时选择 po0 token 或 ggy 链接。
两种服务的请求方式与执行间隔必须保持差异（ADR 0012 的直连入口、ggy 的固定 11 秒）。

## 决定

- 主导航只有一个 `PageLabel.whitelist`（「加白」），页面为 `WhitelistView`；`PageLabel.po0`、`PageLabel.ggy` 删除。
- 配置模型只保留一个总开关 `Po0FirewallProps.enable`，`ggyEnable` 字段删除。旧配置读取时两个开关按 OR 合并：
  任一开启则总开关开启；保存的 JSON 不再出现 `ggyEnable`，因此关闭后重新加载不会再次打开。
  `tokenEntries`、`ggyEntries`、`pollSeconds` 与既有迁移（旧 token 字符串、6.0 混合列表）不变。
- 界面合并为一张混合列表（po0 在前、ggy 在后），持久化仍是两个列表；新增弹窗用类型选择（po0 token / ggy 链接），
  编辑时类型只读，更换类型通过删除后重新添加完成。
- 两个调度器 `Po0Firewall` 与 `GgyFirewall` 继续存在并共用 `enable`，po0 间隔 1～3600 秒可调，ggy 固定 11 秒（0013 不变）。
- 总开关变化引发的 profile 重载由共享的 `WhitelistCoordinator` 串行处理：一次开关变化只重载一次，快速切换以最新意图为准；
  两个调度器在重载完成前不发新请求。协调器不持有轮询计时器，也不直接发送 HTTP 请求。
- 「查询 po0 状态」只对 po0 执行只读查询；「立即加白」对所有已配置的有效条目执行一次加白。
- 结果与条目通过内存中的完整凭据值匹配（`Po0TokenResult.tokenValue`，不持久化、不展示、不写入日志），
  汇总 `WhitelistSummary` 按当前有效条目统计；页面、首页卡片与桌面侧栏共用同一份汇总。
- 首页控制中心的加白卡片固定显示「加白」与共享汇总，不再按 5 秒轮换，点击固定进入加白页。

## 后果

- 0013 中「ggy 作为独立页面与独立开关」「首页卡片轮换」的部分由本 ADR 取代；ggy 固定 11 秒与两套调度器的约束继续有效。
- 手机底部导航从 6 项回到 5 项。
- 旧配置中任一开关开启的用户升级后总开关自动开启，加白行为不变；两边都关闭的用户不受影响。
- 结果的内存匹配字段只存在于运行时状态中：重新生成配置、备份恢复都不包含它，展示与日志继续只使用前 12 位标识。
