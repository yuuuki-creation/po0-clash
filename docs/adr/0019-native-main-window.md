# 0019. 原生版恢复主界面，结构接近 FlClash

- 状态：已采纳
- 日期：2026-10-30

## 背景

ADR 0018 让各端从零设计，macOS 以菜单栏为主、只配一个设置窗口，Windows 只有托盘和小窗口。维护者试用后认为仍然需要
主界面，整体风格要接近原来的 FlClash，样式用苹果最新的液态玻璃规范（iOS 26 / macOS 26）。

## 决定

- 每端都有主界面：左侧（窄屏为底部）导航，页面依次为仪表盘、代理、订阅、加白、设置。
- 仪表盘沿用 FlClash 的卡片网格和右下角的浮动启动按钮（显示已连接时长）；卡片只放功能范围内已有的数据：速率、出口 IP、
  当前节点、模式、接管方式、订阅用量、加白。仍然不做流量图表、连接列表和日志页。
- 代理页沿用 FlClash 的列表样式：每个策略组一张可展开的卡片，展开后是节点卡片网格，选中的节点用强调色描边。
- 样式按苹果的《Adopting Liquid Glass》和 HIG：玻璃只用于浮在内容上方的功能层，内容层不用玻璃，不自绘背景、渐变和发光，
  系统蓝作强调色，图标单色。
  - 桌面端（macOS、Windows）照 macOS 26 的访达：悬浮的玻璃侧边栏；页面标题、副标题和操作放进窗口顶部的统一工具栏，
    操作是纯图标按钮，同类的共用一个玻璃胶囊；内容滚到工具栏下有滚动边缘效果；订阅、加白、设置是分组表单。
  - 手机（Android）照 iOS 26：底部悬浮的胶囊玻璃标签栏，滚动时收起的大标题，右上角的玻璃按钮组，inset grouped 列表。
  - 启动按钮是整个界面唯一着色的主操作（`glassProminent`）。
- macOS 的菜单栏窗口保留，作为快捷入口；原来的设置窗口并入主界面。

## 后果

- 取代 ADR 0018 中「各端从零设计、不参照 Flutter 版的页面结构」与「macOS 以菜单栏为主」两条，其它不变。
- macOS 正常打开应用时显示主界面并出现程序坞图标，关闭主界面后回到只在菜单栏；开机自启不弹出主界面。
